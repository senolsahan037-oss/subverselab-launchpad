# 04 — Certification

## Rule

Products may not leave the Launchpad until every mandatory validation has passed. The Launchpad does not create products — it certifies them. Only certified products may enter production.

Consolidated from `Rules/_legacy/CERTIFICATION_RULE.md`, `Rules/_legacy/LAUNCH_AUTHORIZATION.md`, and `Rules/_legacy/LAUNCH_CHECKLIST.md`, which stated the same rule three times with slightly different emphasis and no single checklist of record. This file is now the single statement of the rule.

## Why

Development folders are allowed to contain incomplete, experimental, or unstable work. Only validated products are permitted to reach production. This guarantees consistent quality, prevents incomplete deployments, and ensures every published product follows the same production pipeline — regardless of who built it or how urgent it feels.

## The checklist

Every product must pass this before deployment. No product proceeds unless every mandatory item passes.

**Prerequisites**
- [ ] Rule compliance: product has been checked against `00_PLATFORM_INVARIANTS.md`.

**Validation** (see `03_VALIDATION.md` for the exact schema)
- [ ] Required files exist: manifest, guide, cover, and content assets are present.
- [ ] Manifest validates against `03_VALIDATION.md` / the live `validateManifestSchema()` in `server.js` — not an older or aspirational schema.
- [ ] Guide is complete, accurate, and matches the manifest — no placeholder or inferred content.
- [ ] Assets validate: covers and media meet the type/size constraints in `03_VALIDATION.md`.
- [ ] Actions validate: product-specific actions work as intended.
- [ ] Previews validate, if present.
- [ ] Metadata is structurally sound and strictly non-inferred.

**Testing & Deployment**
- [ ] QA passes: all local testing and QA checks are complete.
- [ ] Security passes: no known vulnerabilities or unresolved technical debt.
- [ ] Deployment validation passes: see `07_POST_DEPLOY_VERIFICATION.md`.

## Launch authorization

If every mandatory validation succeeds:

```
LAUNCH AUTHORIZED
```

Continue to `05_SYNC.md` → `06_DEPLOYMENT.md` → `07_POST_DEPLOY_VERIFICATION.md`.

If any mandatory validation fails:

```
LAUNCH DENIED
```

Deployment, Metadata Sync, Preview, and Publish must **not** continue if launch is denied.

## Forbidden behavior

- Deploying directly from a development folder.
- Publishing without validation.
- Skipping QA.
- Skipping Metadata Sync.
- Manual website configuration to compensate for missing assets.
- Launching with placeholders, inferred metadata, guessed actions, autogenerated descriptions, or autogenerated guides.
- Bypassing these rules by any AI agent, developer, automation, deployment script, or administrator.
- Continuing to Deployment, Metadata Sync, Preview, or Publish if the validation output is `LAUNCH DENIED`.
