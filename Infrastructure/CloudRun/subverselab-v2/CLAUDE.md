The Launchpad root `CLAUDE.md` applies first. This file is the site's own rules and its single state log (owner 28 Oct 2026:
"durumu claude.md yaz"); it replaces STATUS.md. Pending changes are listed one by one in `RELEASE_QUEUE.md` (NEXT DEPLOY).
Old rules, past states, deploy logs, audits and task briefs are in `_legacy/` — history only, never instructions.

## What this folder is
- Pages: React + Vite, prerendered per route (`scripts/prerender.js`), served by the root `server.js` (no secrets) on Cloud Run
  service `subverselab-site`. Every `/api/*` route is the separate service `subverselab-api` (`api/`, own Dockerfile); the site
  proxies `/api`. Deploy targets and commands: `../../../Rules/DEPLOYMENT_REGISTRY.md`, rollout: `../../../Rules/SITE_RUNBOOK.md`,
  (the site/api split was cut over on 25 Oct; its runbook is history in `_legacy/docs/`).
- Product data: `src/data/plugins.js` (rooms, prices, checkouts, MuseHub links), `samplePacks.js` (generated by
  `scripts/import-sample-packs.js`), `samplePackPrices.js`, `presetPacks.js`, `productDates.js` (store order), `news.js`.
- The live catalogue (owner 31 Oct): items added from /admin → Catalogue (`docs/CATALOG.md`) are laid over that data at page load;
  a saved item shows within a minute, the prerendered HTML follows at the next build.

## Rules for this site
- Local only until the owner says deploy in chat. Gate for every change: `npx eslint .` (0 errors), `npm run build`, every
  `node scripts/test-*.js`, then a NEXT DEPLOY entry in `RELEASE_QUEUE.md` with the numbers. After a deploy, drop the previous
  revision's `--tag`: a tagged old revision keeps its own warm instance and bills (26 Oct: 156 of 175 TRY were idle tags).
- Release rhythm (owner 1 Nov): new products and news go in through /admin → Catalogue, no deploy. The site itself is
  deployed about once a month as general maintenance, batching the NEXT DEPLOY entries; an earlier deploy only when the
  panel turns out to be missing something it needs (still on the owner's go).
- Themes (owner 28 Oct): the light theme is cream everywhere and the dark theme dark green everywhere. Only the products' own
  pictures and device displays (panel screenshots, VFD/key readouts, waveform strips, the JING FANG film) keep their dark ground
  in both. Colours come only from the tokens in `src/index.css` (`:root` and `:root[data-theme="dark"]`); a component never
  styles itself inside a theme block — add a token instead (`--pl-*`, `--room-amt`, `--tour-bg`, `--musehub-*`).
- Boxes are lifted by `--shadow-card` / `--shadow-card-hover`, never framed by a line; no gold lines round boxes in either theme
  (owner 28 Oct). `--color-border` is only for dividers inside a box or between rows.
- Page widths (owner 28 Oct: no wide empty bands either side): every page and layout column uses `--page-max`
  (`min(92vw, 1600px)`, on `.container`, the news, plugin hero, panel tour, listen hero); running text only uses
  `--read-max` (820px: legal, help, manuals, the text half of a product room). No component sets its own pixel max-width for
  a page column. The homepage pack cards span the window and slide in from the screen edges.
- Store order: every product list newest first by its latest release date in `productDates.js`; an update counts as a release.
- Sample packs: run the importer with the pack's `out/<work>/Preview` present; after an import copy the live packs' original
  covers back from `dist/sample-packs/<slug>/`. Never delete `01_AI_Tools/subverselab-packs/out/<work>/Preview` or `cover.*`.
- Local owner preview without Google: `http://localhost:5181/?devpreview=1` (answers from `.devdata/`, gitignored, never built;
  non-GET calls are not sent). `?devpreview=0` turns it off. Dev server: preview config `subverselab-site-dev`, port 5181.
